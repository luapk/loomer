# REVISIT: how a saved style reaches the image model

**Status:** implemented (branch `claude/styles-image-continuity-1dyl4u`)
**Date:** 14 Aug 2026

PROJECT_BRIEF section 3 predates named styles, so nothing there is reversed by
this. It is written up because it decides something section 3 would have
decided had styles existed then: **what carries a look into a frame.**

## The problem

Continuity on STYLE_REF boards was poor. Four causes, in rough order of size.

1. **Four recipes for one look.** `generate-refs`, `generate-shots`,
   `regen-ref` and `regen-shot` each assembled their own style text. Reference
   stills were baked under one recipe and shot frames under another, and a
   regenerated shot under a third — so a re-rendered frame structurally could
   not match the frames either side of it.

2. **Style images are the wrong instrument at shot time.** Gemini has no style
   channel; every attached image is read as "here is a thing that exists".
   `a63320e` capped them at two and `1e98d2a` removed them from shot prompts
   entirely, both for the same reason: past a small number the model sources
   *content* from them and character likeness collapses.

3. **Prose is not a lock.** What replaced the images was a one-or-two sentence
   summary, regenerated from scratch on every image add or remove. The same
   style described itself differently on different days, and the director had
   no way to correct a misreading.

4. **STYLE_REF had quietly lost scaffolding the house styles keep** — the
   depth-of-field line most of all.

## The decision

**Images author the style. Text applies it.**

A style compiles once, at save time, into a structured `StyleSpec`
(`src/schema/style-spec.ts`): medium, palette with hex values, lighting, grade,
texture, line and edge, detail level, a per-style `avoid` list, and a one-line
`reading` for the director. Generation renders that spec to an identical prompt
block on every call.

All style text lives in `src/lib/style-context.ts`. The four routes ask for it.

### Why not keep conditioning on the images

Repeatability is what continuity *is*. Two photographs give the model two
chances to read the look differently on every one of forty-five renders; a
frozen string gives it none. Dropping the images from shot prompts also hands
every reference-image slot back to identity, which matters because quality
plateaus around four conditioning images (brief §3.5).

Reference stills still carry the images. Nothing competes with them there, and
they are what carry the look forward into every shot that conditions on them.

### Why the spec is structured rather than prose

Named fields can be diffed, versioned, and — the point — **edited**. "Reads too
clean, add visible paper tooth" becomes one field, and every future frame
changes. Images alone give the director no dial at all.

### Why `avoid` is per-style rather than a house rule

The watercolour text hardcodes "no anime eyes, no chibi proportions". Applying
that to a saved style would fight a director whose chosen look is stylised, so
each spec states how anatomy should be proportioned for *its own* medium.

## Consequences

- A style with no spec (saved before this, compile failed, no API key) falls
  back to the one-line reading, then to the reference stills. Never blank.
- Removing a style's last image clears the spec rather than leaving one that
  describes images the style no longer has.
- `Style.summary` stays as a column, mirrored from `spec.reading`, so list
  views never parse the spec.
- Compiling costs one Sonnet call per style edit, not per render.

## Revisit if

- **The spec should be director-editable in the UI.** It is structured
  precisely so it can be, and that is the payoff this change sets up without
  collecting. Right now a director who disagrees with the compile can only
  change the images and recompile.
- **`photographic` finds no use.** It is compiled but not yet read. The
  intended consumer is previous-frame spatial chaining, which is currently
  gated on `renderStyle === 'WATERCOLOUR_SKETCH'` — a stand-in for "the output
  medium differs enough from the reference that Gemini reads position instead
  of compositing content". That is a property of the medium, not of the enum
  value, and `photographic` is the honest test. Left alone here to keep the
  change reviewable.
- **Style images want to come back at shot time**, as a single anchor frame
  generated by our own pipeline at the board's aspect ratio and approved
  through the reference-still gate. That was proposal 2 of three and is not
  built.

## Known, not addressed here

- **The board's aspect ratio never reaches Gemini.** `RefEntity.aspectRatio` is
  declared in `src/lib/reference-stills.ts` and never passed;
  `style_lock.aspect_ratio` reaches only the PDF. Every frame renders at the
  model default, so a board declared 2.39:1 is 2.39:1 in the export and not in
  the images. Frame shape is the most visible continuity cue there is.
- **Style images are never resized.** Brief §7.6 mandates 1024px max; a 20MB
  upload goes inline into every reference-still call.
- `check-continuity` still instructs the model to ignore style drift
  ("Style inconsistencies … are a separate concern"). With a spec to check
  against, they need not be.
- `buildGrammarLine` and the single-frame guard remain duplicated between
  `generate-shots` and `regen-shot`.
